# v0.8 项目群与员工接入补全

依据：human 已批准“发现 Agent → 加入项目群 → 共享资料/进度 → 收发信并协作”，并要求先补当前单机功能。保持独立 v0.8，不更改 v0.7 服务。负责人考核、入组审批和派单指定 provider/model/key 是后续方向，本轮不传递或保存供应商 key。

## 实现契约

员工属于全局名册，可以在没有项目时登记。项目成员是独立关联，用户从名册加入成员；退出项目撤销该项目工具凭证，有未结束任务时拒绝移除。保留已有身份、成员关系、历史和设备配对。v5 数据升级前生成 SQLite 快照，迁移在事务内完成。

发现阶段只读：支持的 CLI 保留原生登录状态检查；其它已知 CLI、macOS app 只登记真实入口。app 和 CLI 不自动合并。自动执行仍仅支持 Codex/Claude CLI；登记其它入口不能派执行任务。成员卡展示接入方式、设备、是否支持执行和实际执行验证状态。受管 Codex CLI 会话不附着正在使用的桌面聊天。

项目消息持久保存，默认普通消息/回复不启动模型。Human 或有效员工执行会话可以显式请求一位项目同事协作，原子地保存消息与只读任务。消息、领取、执行完成、人工验收是不同事实。回复线程不得跨项目。携带 request_id 的请求按项目/发送者去重，相同ID不同内容拒绝。员工协作链最多四跳，拒绝向祖先成员反向请求，避免递归唤醒；普通回复不产生协作链。

本机工具凭证绑定 task/run/employee/project，仅执行期间有效；静态成员凭证只允许读取，不允许发信或写笔记。发送者由会话身份决定，不接受工具参数中的发信身份。远端工具写入同时检查设备、员工、项目及当前 task/run。日志不得泄漏工具凭证。

这只能证明受管员工会话归属，不能证明宿主内部调用者是主 Agent 还是共享权限的 subagent。消息显式记录 employee_session 归因和 internal_actor_verified=false。默认指示助手向主 Agent 汇报，不自动成为成员。独立助手入组、授权代发及可靠宿主级权限隔离留待正式接入协议；不声称仅靠提示词已经解决继承权限问题。

## 验证与交付

1. 数据与接口：v5迁移、零项目登记、多项目成员、撤销、普通通信、协作原子事务/去重/循环限制、任务工具凭证失效。
2. 执行接缝：真实HTTP、真实stdio MCP、进程级模拟执行器验证发信触发、回复和人工验收；模拟执行不冒充真实模型验证。
3. 界面：零项目首屏、app/CLI能力说明、添加项目成员、消息与任务分开、按钮操作和拖放替代、双语可访问。
4. 回归与发行：相关测试、完整测试及打包检查。用户现有home保持，替换程序后打开新版工作台。当前工作中的任务先等待结束或明确停止，不能静默打断。macOS签名仍为本地ad-hoc，不宣称公开公证。

## 后续方向

单机闭环验证之后扩展更多Agent执行适配，再完善升级和跨设备。dsh-devices负责人的考核/产品开发小组、运行时provider/model选择与密钥授权应作为独立设计，凭证引用与短时授权优先于把明文key塞进任务或群消息。
