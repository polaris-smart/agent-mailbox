# 家目录布局约定（2026-10-08 · 老板提出「不能无限制新增」✓）

> 问题 ✗：现状是**临时起名**——`~/.agent-mailbox-v08` / `~/.agent-mailbox-empty-before-default-fix-20261001` /
> `/tmp/am-app-build2…11` ✓ 名字随手掌一拍就多一个 ✓ 无从判断「哪个是活的」✗

## 两区定版 ✓（对外可见的目录**只有两个** ✓ 其余一律收进区里 ✗）

```
① 本地运行区（**唯一活库** ✓ 名字不带版本 ✗ 版本记在库内 `SCHEMA_VERSION` ✓）
   ~/.agent-mailbox/                     ← 活的工作台库（信/员工/任务/会话）
   ~/.agent-mail/                        ← v0.7 老信箱（历史 ✓ 只读保留 ✓ 不进新区 ✗）

② 开发与构建区（**唯一开发根** ✓ 名字固定 ✓ 版本作为子目录 ✓）
   ~/.agent-mailbox-dev/
       build/<版本>/                     ← 每次构建的产物（不再散落 /tmp ✓）
       backups/<日期>-<原因>/            ← 迁移前/破坏性操作前的整包备份 ✓
       logs/                             ← 构建与服务日志 ✓

③ 发布物（唯一出口 ✓ 不在 /tmp ✗）
   ~/agent-mailbox-release/<版本>/        ← 可分发的 app / zip / wheel + SHA256 清单 ✓
```

## 硬规矩（写进检查 ✓ 不只是口头 ✗）

1. **家目录下 `.agent-mail*` 只允许 2 个** ✓（`.agent-mailbox` 活库 ✓ `.agent-mail` 老信箱 ✓）
   —— 任何其它名字 ⇒ **必须进 `~/.agent-mailbox-dev/`** ✗（含"修复前备份"这类 ✓ 收进 `backups/` ✓）
2. **不许再出现"带原因的长名字"** ✗（原因写进 `backups/<日期>-<原因>/NOTES.md` ✓ 不写进目录名 ✗）
3. **构建产物一律落 `~/.agent-mailbox-dev/build/<版本>/`** ✓ 且**成功即清中间件** ✗（build/ + cache/ ≈ 1.5G/次 ✓）
4. **发布物一律落 `~/agent-mailbox-release/<版本>/`** ✓ 并附 `SHA256SUMS` ✓（/tmp 会被系统清 ✗）
5. **版本只写在库内与产物名下** ✗ 不写进活库目录名 ✓（避免 `-v09` 这类再长一个 ✗）

## 迁移成本（实测 ✓ 不猜 ✗）

- 活库改名 `~/.agent-mailbox-v08` → `~/.agent-mailbox`：**需同步改** ①工作台服务配置（cordis.patch.yml 的 `sessionFile`）
  ②launchd 单元里的 `--home` ③我们代码里的默认值 ✓ ⇒ **不是纯 mv** ✗ 必须一次改齐 ✓ 否则服务起不来 ✓
- 因此**建议**：先落这份约定 ✓ 新代码/新构建**立即遵守** ✓；改名作为**单独一步**（含上述三处同步 + 一次 e2e 验证 ✓）
