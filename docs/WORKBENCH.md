# v0.8 工作台

本页保留 0.8.0b3 独立实现 Beta 3 的历史边界；公开版本以发行页和 PRD 为准。当前源码候选已新增既有会话邮箱与默认邮件任务，尚未正式发布。[PRD](PRD.md) 是产品边界；[上手](GITHUB-QUICKSTART.md) 和 [节点指南](NODES.md) 是操作入口。没有自动继承 v0.7 的后台服务和 MCP 邮箱配置。

工作台在 loopback 浏览器中打开；CLI 和可选 macOS app 使用同一产品模块。当前源码候选的默认路径是发现员工 → 全局登记 → 创建项目群 → 加入成员、填写职责 → 在原有 App/CLI 导入项目邮箱 MCP → 共享资料、主动查信 → 明确接受邮件任务 → 提交结果 → Human 验收。普通消息、回复和读信不启动模型、不自动接单；邮件任务也不另开 CLI。项目资料在笔记和资源区积累，任务事件形成工作历史。

可选受管执行连接支持 Codex、Claude CLI 适配器。依赖完整、原生登录、首次成功执行分开报告；发现 app 仅是发现。多个员工名称默认共用本机 agent 登录。受管任务由运行器注入 **16 个**项目工具（2026-10-07 追加 5 个只读诊断：graft ask/callers · aoci doctor/status/check）。当前源码候选另提供 **17 个**既有会话邮箱工具（同 5 个诊断**双面挂载**；**远端面未加**，仍 11 个）；在员工详情导出员工/项目/session 绑定的私有配置，导入支持 stdio MCP 的宿主。不能把支持 MCP、配置导出或员工入组当作该真实宿主已成功接入。当前邮箱只支持本机员工，接入本身不表示自动唤醒。

受管任务由一个执行 owner 管理。邮件任务在接受时冻结已批准资料版本并返回 `resource_manifest`，后续 `project_tasks()` 保留清单；用其中 `version_id` 显式读取固定版本，普通无版本读取不自动绑定任务。邮件状态 queued→员工明确接受后 running→提交后 review→Human 验收后 done，提交不等于完成。职责仅说明分工，不授予执行或验收权限。取消、离组、暂停或退役结束活动邮件任务；重启不把原有员工会话当作受管执行中断。运行结束进入待验收；失败、取消、中断都有显式状态。批准操作只能由 human 给出，过期或断线默认拒绝。远端终态先落本机私有回执，再尝试送达；重启恢复只发送原回执，不重复任务。

单机无需设备连接功能。私网节点需显式配对、项目目录映射和员工注册；Ubuntu 节点可无界面运行。代码目录及登录不自动同步，主控须开着。本机回环验证不能证明真实跨国节点体验。

升级采用应用/数据分离。同 home 的兼容 v0.8 升级保留项目、身份和授权；当前不是自动更新系统。macOS app 没有 Developer ID 证书；Beta 1 的 Ubuntu 24.04 ARM64 容器源码节点已完成跨 OS 协议验证，不当作本轮 Linux 实体设备验收；Beta 3 当时的 Windows native 发行、通用 workflow 编辑和成本治理限制须与后续发行记录区分；本机 Git 独立工作区在 Beta 3 提供，平台实测单独列证据。

每张员工卡的“查看信箱”以及侧栏“员工信箱”可打开个人通信视图，切换收件箱、发件箱和项目群消息。你仍以管理员身份查看；发信请打开对应项目对话，发送者仍为 Human。Agent 使用绑定的既有邮箱或受管项目工具，不使用你的 owner 网页凭据。

## 员工侧信箱

当前源码候选默认给既有 App/CLI 导出项目邮箱配置，宿主导入后由员工主动查信，不自动唤醒。受管执行仍可自动获得独立的项目工具，不需手工配置受管运行器。`project_messages()` 是本人的收件；`project_messages(folder="sent")` 是发件；`project_messages(folder="group")` 是当前项目群。返回最近最多 100 条，`has_older` 表示更早记录仍在库中，历史分页尚未提供。自己的广播归发件。查看不会触发任务或标记已处理。支持 stdio MCP 配置的现有 App/CLI 可以尝试接入邮箱，不要求 CLI 执行适配器；登记 App 不代表宿主已导入、实际调用或可自动控制。管理员“员工信箱”与员工工具视图不同，没有独立员工登录页。

后续体验和协作建议见[用户旅程与路线图提案](designs/2026-09-30-v08-user-journey-roadmap.md)，不代表已经实现。

## 语言、版权与升级

页脚显示 NoFox、运行中的版本、Apache-2.0 与 GitHub。点击版本或协议打开“关于与更新”：可切换跟随浏览器/简体中文/英文，并展开阅读 LICENSE、NOTICE、原 MIT 声明。语言仅改变 UI，原始项目内容不自动翻译。偏好保存在浏览器，切换重载页面。

是否已有公开发行以发行页和 PRD 为准；当前源码候选尚未正式发布，更新流程不会自动下载替换程序。关于页可选择稳定/Beta 渠道并显式检查 GitHub。点击“准备升级”持久暂停新任务领取；已有任务继续，队列保留。任务、未确认领取和回执结束后，生成私有校验备份，再退出、替换同平台包并使用原目录启动。重启后暂停仍保留，确认正常后显式恢复接单。默认 Mac home 为 ~/.agent-mailbox-v08；自定义 home 继续使用自定义路径。发生数据迁移失败时停止使用，按对应版本说明恢复备份；不能保证简单降级即可读取迁移后的数据库。公开 GitHub 最新版本不必等于本地 Beta。

### 项目资料与代码检索（0.8.0b3）

在项目资料页点击“查看资料”可查看实时文本、读取时间和内容校验值。HTML 可选隔离预览，外部脚本、网络请求和父页面访问被阻止。报告需为自包含单文件；实时预览不是固定版本；在“固定版本”入口冻结/确认后，版本预览使用保存的快照。

“检查 CodeGraph”检查本机可选工具及当前项目已有索引；不会自动安装、建立或更新索引。查询只返回代码符号，最多 10 条，新鲜度未知不能当作最新源码证据。员工 MCP 可用 `project_code_search(query)`；远端返回协调端项目索引，而非远端 checkout 的一致性证明。详细发布门槛见 [Beta 验收](BETA-ACCEPTANCE.md)。

### Beta 1：版本、日志与节点

以下为 Beta 1 历史边界，不覆盖当前源码候选的邮箱会话写权限。Schema 6→7 自动建立不可变资料版本、批准记录和任务版本清单，迁移前生成 0600 私有 SQLite 备份；失败回滚。应用/数据分离，同一个 home 更新保留已有员工与项目。员工只有有效 task/run 才能提案或发信；任何带执行标识的远端读取也在结束/取消后拒绝。内部 subagent 的真实作者不独立核实，归因仍是注册员工会话，不把这当作完全隔离助手的保证。

源码 Beta 不含自动更新器；macOS app 自带执行运行组件但没有 Developer ID 公证。可选 CodeGraph 只在 macOS/Linux 查询已有索引，新鲜度仍是未知。


## Beta 2 更新准备

Schema 7→8 增加更新渠道、持久接单暂停和未确认远端领取记录，迁移前仍生成私有 SQLite 备份。暂停与领取由同一数据库事务序列协调；未知的网络领取结果不会被当作空闲。关于页显示实际运行平台、架构、home 和安装方式，提供 App/wheel/源码对应步骤。

更新检查只在点击时请求固定仓库公开 release 列表，稳定渠道排除预发布，Beta 包含稳定版。按数字比较 a/b/rc/正式版；不会把公开旧版提示成升级。网络、限流、格式或过大响应显示未核实，清除旧检查结果。未知节点仍使用既有 v1 流程但标为未确认；明确协议不兼容时拒绝新领单，已有回执可继续提交。节点报告是已认证设备的自述，不能证明其二进制来源。

更新备份位于该 home 的 `update-backups/`，目录0700、文件0600，包含一致性 SQLite、workbench 内身份和配对配置，附 SHA-256 manifest；不包含可重建执行runtime、缓存、日志、旧迁移备份、临时 owner token/lock、项目源码、home/task-workspaces 内独立工作区及各供应商外部登录。外部项目应自行使用 Git/备份。备份失败仍暂停，可重试或恢复；准备等待或失败时不能从更新流程直接退出。备份是记录时刻的快照，后续新增记录不属于它。恢复备份需要匹配程序版本，不能简单用旧程序读取迁移后的数据库；当前没有自动回滚。

关于页和设备页报告节点版本/协议。已停止监听时仍可展示最后认证报告，旧报告不等于设备在线或当前软件证明。真实 HK/US 与 Windows 安装升级尚未验收。

## Beta 3 接入与交付

入组后在员工详情查看接入检查，查看不启动模型。显式验证创建只读任务，可选择模型，会使用原生模型额度并沿用权限审批。随机标记的上下文读取与笔记工具回执、正常任务结束共同构成验证；文本“成功”不是证明。远端 probe 暂不支持，App 未有适配器不可自动执行。

本机“允许修改”任务使用干净 Git 根目录的独立 worktree，路径为 home/task-workspaces/<task-id>。不是 OS 沙箱，不隔离该设备原生账号。任务详情显示固定交付、文件差异、原始基线、员工报告及系统事实；没有系统测试证据就显示未验证。验收与合入分开：通过验收后确认合入，原仓库 HEAD/干净状态和 patch 校验必须通过，不自动 commit/push。退回修改填写说明，创建关联任务；基线一致时新 worktree 继承上一轮固定 patch。

`project_delivery(task_id)` 为本项目员工提供同事固定交付，项目 MCP 共 **16 个**工具（2026-10-07 追加 5 个只读诊断：graft/aoci ✓），不开放任意工作区文件下载。远端修改任务暂拒绝；只读通信不受影响。工作区保留，不自动删除；SQLite 更新备份不包含它或外部 Git，应单独备份代码与工作区。[Beta 3 证据](evidence/v080/beta3-collaboration.md)区分自动测试、真实 provider 和平台验证。
