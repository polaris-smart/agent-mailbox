# v0.8 工作台

当前 0.8.0a7 为独立实现 alpha。[PRD](PRD.md) 是产品边界；[上手](GITHUB-QUICKSTART.md) 和 [节点指南](NODES.md) 是操作入口。没有自动继承 v0.7 的后台服务和 MCP 邮箱配置。

工作台在 loopback 浏览器中打开；CLI 和可选 macOS app 使用同一产品模块。普通用户的路径是发现员工 → 全局登记 → 创建项目群 → 加入成员 → 消息/协作请求 → 操作审批 → 结果验收。普通消息和回复不启动模型；请求协作才创建只读任务。项目资料在笔记和资源区积累，任务事件形成工作历史。

当前执行连接支持 Codex、Claude CLI 适配器。依赖完整、原生登录、首次成功执行分开报告；发现 app 仅是发现。多个员工名称默认共用本机 agent 登录。项目 MCP 工具只注入受管任务，用户原有 app 对话需其厂商支持的正式接口才能另行接入。

任务由一个执行 owner 管理。运行结束进入待验收；失败、取消、中断都有显式状态。批准操作只能由 human 给出，过期或断线默认拒绝。远端终态先落本机私有回执，再尝试送达；重启恢复只发送原回执，不重复任务。

单机无需设备连接功能。私网节点需显式配对、项目目录映射和员工注册；Ubuntu 节点可无界面运行。代码目录及登录不自动同步，主控须开着。本机回环验证不能证明真实跨国节点体验。

升级采用应用/数据分离。同 home 的兼容 v0.8 升级保留项目、身份和授权；当前不是自动更新系统。macOS app 没有 Developer ID 证书；Windows/Linux 的 native 发行、真实节点上手、workflow、独立工作区和成本治理仍有待后续完成。

每张员工卡的“查看信箱”以及侧栏“员工信箱”可打开个人通信视图，切换收件箱、发件箱和项目群消息。你仍以管理员身份查看；发信请打开对应项目对话，发送者仍为 Human。Agent 使用受管会话中的项目工具，不使用你的 owner 网页凭据。

## 员工侧信箱

Agent 通过受管会话自动获得项目工具，不需逐个手工配置 MCP。`project_messages()` 是本人的收件；`project_messages(folder="sent")` 是发件；`project_messages(folder="group")` 是当前项目群。返回最近最多 100 条，`has_older` 表示更早记录仍在库中，历史分页尚未提供。自己的广播归发件。查看不会触发任务或标记已处理。支持执行适配器的 CLI 能使用这一入口；登记 app 不代表可注入或自动执行。管理员“员工信箱”与员工工具视图不同，没有独立员工登录页。

后续体验和协作建议见[用户旅程与路线图提案](designs/2026-09-30-v08-user-journey-roadmap.md)，不代表已经实现。
