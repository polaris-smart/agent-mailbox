# agent-mailbox v0.8.0a1 工作台预览

这是从 v0.7.6 接手栈 `a7e1094` 开出的独立实现，分支 `feat/v080-workbench`。v0.7.6 的发版、运行中服务和正式 PRD 不在本次修改范围。这里记录预览版实际能力，不能作为正式发行说明。

## Human 如何使用

macOS ARM64 本机构建会生成 **Agent Mailbox.app**。应用自带 Python、Node、固定版本的执行适配器，双击后在本机浏览器打开工作台。应用包与数据分开；替换应用包不会重新创建员工、项目、日志、记忆或设备凭据。本轮未完成 Developer ID 签名、公证、自动下载更新，GitHub 上也还没有这个版本可供安装。

1. 选择已有项目目录。
2. 发现并加入已安装、已登录的 Codex 或 Claude Code 员工。
3. 交代任务与验收标准。执行结果先进入“待验收”，由你通过或退回。

管理工作台本身不需要 LLM、API key。真正执行工作的员工仍需要自己的账号和可用模型；不会把应用当成一个新的模型供应商。受管会话获得项目上下文与专属 MCP 工具，不要求 human 逐个编辑全局 MCP 配置。本轮没有接管任意已经打开的 agent App 对话。

Codex 可以在任务里显式选择本机 CLI 广告的模型。默认复用员工设置，不静默替换模型。远端员工的可用模型没有被主控冒充，因此远端默认复用其自身设置。本机原配置 `gpt-6.1-sol` 在 CLI 中被拒绝，本轮修正了适配器将此错误当文本成果返回的情况；后续验证显式采用 `gpt-6-luna / low`。

## 项目中的共享与沉淀

- 员工成员表、任务状态、验收记录与工作时间线按项目保存。
- PRD、todo-list、daily-update 以及 Aico-code、archify、graft、codegraph 的**文本产物**可以登记为共享资源。不是强制先装七个工具。
- 资源目前只支持已有 UTF-8 文本文件，单文件上限 1 MiB；目录、数据库、二进制和凭据文件不能直接登记。
- 项目记忆带来源。human 记录与 `employee:<id>` 提案分开；agent 不能自动把自己的笔记升级成 PRD 正典。
- 专属工具包含项目上下文、记忆搜索、资源读取、员工笔记和同项目同事消息。消息形成受管任务，自动触发接收员工；发送成功、执行结束、human 验收是三个事实。

当前提供基础项目记忆与文本搜索，没有向量数据库、独立 memory 服务、自动遗忘或智能摘要。每个任务是独立受管会话，跨任务共享项目资料与记忆；没有宣称跨任务复用同一条原生对话。

## 多设备

主控的“设备”页显式开启接入，填写该机的私有 IPv4 地址，选择授权项目，生成五分钟内一次性邀请码。另一台设备运行相同应用，粘贴邀请，为授权项目选择**该设备已有的本地目录**，加入该机员工。随后在主控派单和验收。

证书指纹固定、设备凭据和项目权限分开；设备凭据不能调用 human 管理 API。配对不复制账号凭据、不自动同步仓库文件，也不把主控文件路径冒充远端路径。撤销后旧凭据失效；主控发新邀请、远端明确断开旧连接，才能重新配对。程序重启保留目录映射与身份。无法确认的执行标记为中断，不自动重跑。

远端额外权限请求在本预览版默认拒绝，尚未实现主控批准后回传远端的流程。远端任务运行成功仍须 human 验收。网络等待采用事件唤醒的阻塞请求；界面采用认证事件流，没有固定间隔扫描任务。

最终 Python 测试 **660 passed, 1 skipped**；浏览器 **25 项**。详见[验证记录](evidence/v080/verification.md)。

## 已验证与还没验证

| 项目 | 证据与边界 |
|---|---|
| 状态与安全边界 | 原子领取、同员工跨项目串行、不同员工并行、审批超时/晚批、取消、重启、项目隔离、备份和迁移测试 |
| 管理界面 | 25 项真实 HTTP/SQLite/TLS 浏览器断言；执行与发现为明确标识的 fixture，无真实模型 |
| ACP 组件 | 29 项真实子进程测试，模拟 ACP 对端；动态 MCP、模型与强度、原生 mode、长输出、权限、恢复和错误判定 |
| 同事消息与共享工具 | 真实 stdio MCP 协议 + 模拟执行子进程，证明成员可见、跨项目拒绝、消息触发同事与项目笔记 |
| 设备协议 | 两套隔离 home、本机 HTTPS，对 scope、证书、邀请码、回执、撤销和恢复做验证；不是物理局域网实测 |
| 真实员工 | Codex CLI 0.158.0、gpt-6-luna / low、只读任务，成功返回自动提供的项目记忆标记 `MAILBOX_CONTEXT_OK` |
| 原生 MCP 调用 | 真实模型主动调用注入 MCP 的试验未成功；模型报告 tool runner 不可用。独立/冻结 stdio MCP 通过，原生适配器端到端仍待联调 |
| 公开发行 | 没有发 tag/push/Release，没有签名、公证或自动更新；Windows/Linux 的安装包未构建 |

因此本轮成果是可运行、可审查的 alpha，不能宣布 v0.8.0 全面发布或所有 agent 已零障碍协作。下一轮优先解决原生 MCP 调用、真实第二设备、远端审批和发行更新链路，再扩 agent 类型、语义记忆与 AI ERP。
