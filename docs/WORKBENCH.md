# v0.8 工作台

当前 0.8.0b2 为独立实现 Beta 1。[PRD](PRD.md) 是产品边界；[上手](GITHUB-QUICKSTART.md) 和 [节点指南](NODES.md) 是操作入口。没有自动继承 v0.7 的后台服务和 MCP 邮箱配置。

工作台在 loopback 浏览器中打开；CLI 和可选 macOS app 使用同一产品模块。普通用户的路径是发现员工 → 全局登记 → 创建项目群 → 加入成员 → 消息/协作请求 → 操作审批 → 结果验收。普通消息和回复不启动模型；请求协作才创建只读任务。项目资料在笔记和资源区积累，任务事件形成工作历史。

当前执行连接支持 Codex、Claude CLI 适配器。依赖完整、原生登录、首次成功执行分开报告；发现 app 仅是发现。多个员工名称默认共用本机 agent 登录。项目 MCP 工具只注入受管任务，用户原有 app 对话需其厂商支持的正式接口才能另行接入。

任务由一个执行 owner 管理。运行结束进入待验收；失败、取消、中断都有显式状态。批准操作只能由 human 给出，过期或断线默认拒绝。远端终态先落本机私有回执，再尝试送达；重启恢复只发送原回执，不重复任务。

单机无需设备连接功能。私网节点需显式配对、项目目录映射和员工注册；Ubuntu 节点可无界面运行。代码目录及登录不自动同步，主控须开着。本机回环验证不能证明真实跨国节点体验。

升级采用应用/数据分离。同 home 的兼容 v0.8 升级保留项目、身份和授权；当前不是自动更新系统。macOS app 没有 Developer ID 证书；Ubuntu 24.04 ARM64 源码节点已完成跨 OS 协议验收；Windows native 发行、通用 workflow 编辑、独立工作区和成本治理仍有待后续完成。

每张员工卡的“查看信箱”以及侧栏“员工信箱”可打开个人通信视图，切换收件箱、发件箱和项目群消息。你仍以管理员身份查看；发信请打开对应项目对话，发送者仍为 Human。Agent 使用受管会话中的项目工具，不使用你的 owner 网页凭据。

## 员工侧信箱

Agent 通过受管会话自动获得项目工具，不需逐个手工配置 MCP。`project_messages()` 是本人的收件；`project_messages(folder="sent")` 是发件；`project_messages(folder="group")` 是当前项目群。返回最近最多 100 条，`has_older` 表示更早记录仍在库中，历史分页尚未提供。自己的广播归发件。查看不会触发任务或标记已处理。支持执行适配器的 CLI 能使用这一入口；登记 app 不代表可注入或自动执行。管理员“员工信箱”与员工工具视图不同，没有独立员工登录页。

后续体验和协作建议见[用户旅程与路线图提案](designs/2026-09-30-v08-user-journey-roadmap.md)，不代表已经实现。

## 语言、版权与升级

页脚显示 NoFox、运行中的版本、Apache-2.0 与 GitHub。点击版本或协议打开“关于与更新”：可切换跟随浏览器/简体中文/英文，并展开阅读 LICENSE、NOTICE、原 MIT 声明。语言仅改变 UI，原始项目内容不自动翻译。偏好保存在浏览器，切换重载页面。

当前 Beta 尚未公开发行，不会自动下载替换程序。关于页可选择稳定/Beta 渠道并显式检查 GitHub。点击“准备升级”持久暂停新任务领取；已有任务继续，队列保留。任务、未确认领取和回执结束后，生成私有校验备份，再退出、替换同平台包并使用原目录启动。重启后暂停仍保留，确认正常后显式恢复接单。默认 Mac home 为 ~/.agent-mailbox-v08；自定义 home 继续使用自定义路径。发生数据迁移失败时停止使用，按对应版本说明恢复备份；不能保证简单降级即可读取迁移后的数据库。公开 GitHub 最新版本不必等于本地 Beta。

### 项目资料与代码检索（0.8.0b2）

在项目资料页点击“查看资料”可查看实时文本、读取时间和内容校验值。HTML 可选隔离预览，外部脚本、网络请求和父页面访问被阻止。报告需为自包含单文件；实时预览不是固定版本；在“固定版本”入口冻结/确认后，版本预览使用保存的快照。

“检查 CodeGraph”检查本机可选工具及当前项目已有索引；不会自动安装、建立或更新索引。查询只返回代码符号，最多 10 条，新鲜度未知不能当作最新源码证据。员工 MCP 可用 `project_code_search(query)`；远端返回协调端项目索引，而非远端 checkout 的一致性证明。详细发布门槛见 [Beta 验收](BETA-ACCEPTANCE.md)。

### Beta 1：版本、日志与节点

Schema 6→7 自动建立不可变资料版本、批准记录和任务版本清单，迁移前生成 0600 私有 SQLite 备份；失败回滚。应用/数据分离，同一个 home 更新保留已有员工与项目。员工只有有效 task/run 才能提案或发信；任何带执行标识的远端读取也在结束/取消后拒绝。内部 subagent 的真实作者不独立核实，归因仍是注册员工会话，不把这当作完全隔离助手的保证。

源码 Beta 不含自动更新器；macOS app 自带执行运行组件但没有 Developer ID 公证。可选 CodeGraph 只在 macOS/Linux 查询已有索引，新鲜度仍是未知。


## Beta 2 更新准备

Schema 7→8 增加更新渠道、持久接单暂停和未确认远端领取记录，迁移前仍生成私有 SQLite 备份。暂停与领取由同一数据库事务序列协调；未知的网络领取结果不会被当作空闲。关于页显示实际运行平台、架构、home 和安装方式，提供 App/wheel/源码对应步骤。

更新检查只在点击时请求固定仓库公开 release 列表，稳定渠道排除预发布，Beta 包含稳定版。按数字比较 a/b/rc/正式版；不会把公开旧版提示成升级。网络、限流、格式或过大响应显示未核实，清除旧检查结果。未知节点仍使用既有 v1 流程但标为未确认；明确协议不兼容时拒绝新领单，已有回执可继续提交。节点报告是已认证设备的自述，不能证明其二进制来源。

更新备份位于该 home 的 `update-backups/`，目录0700、文件0600，包含一致性 SQLite、workbench 内身份和配对配置，附 SHA-256 manifest；不包含可重建执行runtime、缓存、日志、旧迁移备份、临时 owner token/lock、项目源码及各供应商外部登录。外部项目应自行使用 Git/备份。备份失败仍暂停，可重试或恢复；准备等待或失败时不能从更新流程直接退出。备份是记录时刻的快照，后续新增记录不属于它。恢复备份需要匹配程序版本，不能简单用旧程序读取迁移后的数据库；当前没有自动回滚。

关于页和设备页报告节点版本/协议。已停止监听时仍可展示最后认证报告，旧报告不等于设备在线或当前软件证明。真实 HK/US 与 Windows 安装升级尚未验收。
