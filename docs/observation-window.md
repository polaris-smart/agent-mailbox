# 观察窗（完成判据 · 事件计数，不是日历）

> 与 HS 共识：**"四线 30 天真实使用"是观察窗，完成定义必须是可数的东西**。
> 判据（全部由 `agent-mailbox observe` 从账本实时算出）：

| 判据 | 含义 | 由什么算 |
|---|---|---|
| **0 风暴** | 窗口内没有触发任何反风暴闸门 | `message_folded` + `thread_frozen` + `escalation_suppressed` 计数 |
| **0 丢失** | 抽样信件**全部可端到端还原** | `audit_chain()` 抽样（默认 20 封）：必须有 ≥2 步且落到终态 |
| **≥10 次真验收** | 人验收过 10 单（`review → done` 是人推进的） | `tasks.status='done'` 且 `updated_at` 在窗口内 |
| **审计抽样 20/20** | 同上，比例必须 1.0 | 抽样可还原数 / 抽样数 |

## 怎么用

```sh
agent-mailbox observe --start          # 记录起点（幂等：重复执行不覆盖）
agent-mailbox observe                  # 随时评估当前四项
agent-mailbox observe --json           # 机器可读（供团队墙/简报消费）
```

## 要点

- **起点只记一次**：写一条 `observation_started` 治理事件；重复调用返回原起点，
  防止"重新开始计时"把窗口洗白；
- **只统计窗口内**发生的事（消息、任务、闸门事件都按 `created_at >= 起点` 过滤）；
- **只读**：`observe`（不带 `--start`）与 `window()` 不写任何东西（有测试）；
- **"0 丢失"的实现方式**：不去定义"丢失"这个模糊词，而是要求**每封信都能被还原** ——
  这正是我们真正害怕的失败模式（当天风暴里"没人说得清全局"）；
- 达标前 `verdict` 显示"观察中"，绝不粉饰。
