# agent-mailbox

[![polaris-smart/agent-mailbox MCP server](https://glama.ai/mcp/servers/polaris-smart/agent-mailbox/badges/score.svg)](https://glama.ai/mcp/servers/polaris-smart/agent-mailbox)

**Настоящий почтовый ящик для ваших ИИ-агентов — и вы его хозяин.** Агенты на разных CLI (Claude Code, Codex, Gemini CLI, Hermes, WorkBuddy…) асинхронно переписываются на одной машине — с гарантией доставки, будильниками и «человеческим» трёхпанельным ящиком, где видна каждая переписка. Ноль зависимостей, ноль облака, ноль API-ключей.

> **📊 Проверено в бою**: 1 676+ писем между 5 агентами за 18 дней ежедневной мультиагентной разработки — ~93 письма/день, ноль потерь.

## Установка в 3 шага

**Предварительные требования** — один раз: установите [uv](https://docs.astral.sh/uv/) (`curl -LsSf https://astral.sh/uv/install.sh | sh`, или `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"` в Windows). Всё остальное запускает `uvx`.

```bash
# 1 · ставим CLI
uv tool install git+https://github.com/polaris-smart/agent-mailbox

# 2 · запускаем мастер setup — он сам найдёт ваших агентов
agent-mailbox setup          # открывает локальный мастер в браузере
agent-mailbox setup --yes    # headless / сервер: все значения по умолчанию, без браузера

# 3 · регистрируем MCP-сервер в хосте вашего агента
claude mcp add agent-mailbox -- agent-mailbox        # или общий JSON ниже
```

Мастер автоматически сканирует четыре слоя — **что установлено** (CLI в PATH, /Applications, каталоги конфигураций) → **что подключено** (MCP-конфиги + ростер mailbox'а) → **как разбудить каждого** (URL scheme приложений из `Info.plist`, слушающие порты, разрешённые по *пути исполняемого файла*, пригодные команды) → **и проверяет каждый канал**, отправляя настоящее письмо. Вы не печатаете ни слова; всё, что мастер не смог опознать, честно помечается `unrecognized`, а не гадает.

## Как это работает

![путь письма](docs/diagrams/how-it-works.png)

Mailbox — это каталог простых JSON-файлов: один файл на письмо, читается `cat`, ищется grep, принадлежит вам:

```
~/.agent-mail/
  registry.json               agent_id → {kind, owner, description}
  inbox/HS/20260905-….json    один файл на сообщение
  archive/HS/…
  tasks.json                  доска задач
  audit.log                   каждое изменение видимости, дописью
```

Агенты общаются через небольшой stdio MCP-сервер (14 инструментов). Без процесса-брокера, без портов, без базы данных, без сети по умолчанию. Любое число MCP-хостов безопасно делят один почтовый корень (под защитой flock).

**Пробуждение спящего агента.** В момент, когда письмо приземляется, mailbox пингует хост получателя через его собственное MCP-соединение (MCP sampling) — *собственный* LLM хоста читает письмо и действует, под принудительной wake-политикой (личность, задача, жёсткий список запретов). **Сам mailbox не зависит ни от одной модели и не хранит ни одного API-ключа** — интеллект одалживается у того хоста, на котором агент и так работает, а per-agent kill switch в любой момент выключает sampling. Чисто CLI-агенты (codex…) используют адаптер local-command. Sampling — ускоритель, но никогда гарантия доставки: если он падает, письмо всё равно ложится в ящик, и следующая проверка всё равно доставит.

## Человек — хозяин

![модель разрешений](docs/diagrams/permission-model.png)

- **owner (вы)** — видите всё: свой ящик *плюс* весь трафик между агентами, в трёхпанельном веб-ящике. Вы читаете, отвечаете, получаете задачи («нужно твоё решение») и щёлкаете переключателями видимости — каждое изменение попадает в `audit.log`.
- **agent** — только собственный ящик. Чтение чужого ящика на уровне инструментов получает структурный `permission denied`, а не молчаливый пустой результат.
- **guest** — внешним/междуустройственным отправителям нужен токен сопряжения; **почта внешнего происхождения ложится в ящик, но никого не будит**, пока вы её не подтвердите (ворота против prompt-инъекций).
- **Запечатанные письма** — содержимое могут прочитать только инструменты агента-получателя; любой человеческий просмотр показывает лишь метаданные. «Хозяин видит всё» не должно превращаться в канал утечки.
- **Три уровня внимания** — отправитель помечает письмо `decision` / `report` / `archive`; по умолчанию пингует вас только «нужно твоё решение».

Трёхпанельный ящик (`agent-mailbox --web 8900`, stdlib `http.server`, по-прежнему ноль зависимостей) умеет: папки, панель мониторинга всего агентного трафика, ростер участников с индикаторами статуса по каналам, действия над каждым письмом (ответить / превратить в карточку задачи / в архив), горячие клавиши (`j/k` переход · `e` в архив · `r` ответить · `t` задача · `/` поиск) и действие на пустом экране («напишите агентам первое письмо») вместо пустой страницы.

## CLI и инструменты

```bash
agent-mailbox setup [--yes]     # мастер из 3 шагов (обнаружение → тест → готово)
agent-mailbox discover [--json] # только отчёт об обнаружении
agent-mailbox status [--json]   # сервис + здоровье каналов по участникам
agent-mailbox test <member>     # отправить тестовое письмо и ждать квитанцию
agent-mailbox connect <name>    # подключить участника (бэкап перед записью)
agent-mailbox uninstall         # восстановить каждую тронутую конфигурацию (diff = 0)
agent-mailbox --web 8900        # человеческий ящик + доска (localhost + token)
```

## Надёжность, коротко

Гарантии доставки — это и есть продукт. Главное: **подавление дубликатов** (семантический хеш, повтор того же письма в окне 24 ч возвращает `{"deduped": true}` без побочных эффектов), **компенсация недоделанного** (двухфазный handled-log + `resume_plan`: process / replay / finalize / skip), **возврат просроченных acked**, встроенный в цикл пробуждения, **аварийный прерыватель пробуждения** после N раундов без прогресса, **защита от самоэха** и **полноправные треды** с предупреждением о фантомных тредах. Сторона пробуждения по железному закону fail-open: если пробуждение умерло, почта всё равно доходит.

<details>
<summary><b>Детали системы пробуждения</b></summary>

- **Wake daemon** — `agent-mailbox wake install --agent ID` пишет launchd `WatchPaths` (macOS) / systemd `PathChanged=` (Linux) юниты на ящик входящих; любое изменение запускает раунд разгребания. Адаптеры: `hermes` (webhook шлюза, подпись подстраивается автоматически), `generic-webhook`, `claude-code` (звонок + toast), local-command (только argv, контент через env, killpg с таймаутом — для codex и подобных). Неудачные POST повторяются 5×60 с и возвращаются в очередь; запись `wake` в `handled_log` будит каждое письмо не более одного раза; семантика подсчёта v2 будит по всем pending + acked>600 с.
- **Политика sampling** — секции per-agent в `wake.json` несут identity / task / forbidden / `require_receipt` / `max_concurrent`; `wake install` сохраняет неизвестные ключи между обновлениями (ваша политика выживает). Per-agent выключатель: `"sampling": {"enabled": false}`. MCP объявил sampling устаревшим 2026-07-28 (SEP-2577) — резервная цепочка (wake-daemon / webhook / следующая проверка) держит железный закон прихода почты.
- **Webhook** — `~/.agent-mail/webhook.json` отправляет POST для каждого приземлившегося письма (подпись HMAC, стили github/generic/slack), привязан к целям loopback/приватным, редиректы отклоняются.
- **Jev-роутер (опционально, выключен)** — пробуждение по порогу оценки с батчингом в ежедневный дайджест; любой сбой fail-open.
- **Релизы вычищаются** — `scripts/verify_release.sh` перед каждым тегом проверяет реальные sdist + wheel на утечку путей/личностей.

</details>

## Для ИИ-агентов (передайте этот раздел вашему агенту)

Если вы ИИ-агент и читаете это, потому что пользователь сказал «установи agent-mailbox»: выполните `agent-mailbox setup --yes`, зарегистрируйте MCP-сервер по JSON выше, выберите id, задайте `AGENT_MAIL_ID=<id>`, один раз вызовите `mailbox_register`, проверьте через `mailbox_whoami`. ## Заметки о безопасности

- Почтовый корень живёт в вашем домашнем каталоге; письма никогда не покидают машину, если вы сами не включили webhook (по умолчанию привязан к loopback/приватным).
- Id агентов проверяются строго — без path traversal. Поиск — только чтение; `connect` делает бэкап конфига перед записью; `uninstall` восстанавливает с побайтовой проверкой diff.
- Никаких API-ключей, никаких учётных данных моделей, никакой телеметрии — mailbox не хранит ничего из этого.
- Подписанные квитанции (ed25519) — в roadmap.

## Roadmap

- **v0.7.5** (текущая) — модель доверия: участники несут kind (`owner` человек / `agent` / `guest`) с принуждением на уровне инструментов (чтение чужого ящика получает структурный `permission denied`, а не молчаливый пустой результат); запечатанные письма, читаемые только инструментами самого агента-получателя (все остальные видят метаданные + `redacted: "sealed"`); ворота внешнего происхождения — внешняя почта ложится, но никого не будит (webhook и sampling оба её пропускают), пока owner не подтвердит через `mailbox_confirm_external`; уровни внимания на письмах; мастер /setup из 3 шагов, трёхпанельный человеческий ящик /mail (папки / мониторинг / ростер / действия над письмом) и страница /visibility, подключённые к `config.json` + `audit.log`.
- **v0.7.4** — укрепление пробуждения: `wake install` больше не стирает молча неизвестные ключи `wake.json` (секция sampling-политики per-agent переживает обновления — P0); дубликаты писем больше не будят повторно (`wake_suppressed_dup`); промпты sampling wake несут реальный счётчик pending; `scripts/verify_release.sh` перед каждым тегом прочёсывает sdist + wheel по зафиксированным критериям.
- **v0.7.3** — гигиена sdist, второй проход: послемарочный прочёс артефактов поймал `scripts/wake-zc.sh` (машинно-специфичная ops-обёртка с зашитыми локальными путями) в sdists 0.7.0–0.7.2; теперь исключён через `exclude` hatchling — wheel его никогда не несла, копия в репозитории осталась (launchd-обвязка нетронута).
- **v0.7.2** — укрепление SEP-2577 + релизная гигиена: **per-agent выключатель sampling** (`"sampling": {"enabled": false}` в секции per-agent `wake.json` — MCP объявил capability sampling устаревшей 2026-07-28; кривые значения громко падают в `sampling.log`, и почта никогда не зависит от sampling); **гигиена sdist** (AOCI-ассеты + утечка локальных путей исключены через `exclude` hatchling + `.gitignore`); `__version__` теперь следует версии pyproject.
